# Motion V3 Reference Analysis

## Reference

- Primary: `https://www.shopify.com/editions/winter2026`
- Supporting lens: selected Awwwards portfolio, typography, one-page, project, and gallery examples documented in the existing design audit.
- Local evidence: Playwright captures in `output/playwright/motion-v3-phase-*`.

## What The Reference Actually Does

### World before pages

`OBSERVED`: Shopify Editions keeps typography, material, imagery, camera behavior, and transition objects inside one Renaissance world. A chapter changes, but the world does not reset.

`LOCAL TRANSLATION`: Tree Hey is one impossible field notebook. Paper, photographs, project screens, film, loose objects, notes, and the closing cover are states of the same notebook rather than section themes.

### A transition explains origin

`OBSERVED`: A book, frame, torn surface, or scene object becomes the next information container. The transition carries meaning rather than only hiding the previous screen.

`LOCAL TRANSLATION`: One Nanjing photograph becomes a pinned fragment, then the NJU Match screen, a film frame, a loose print, a community note, and the final memory.

### One dominant action per beat

`OBSERVED`: Large camera or object motion is supported by quiet secondary depth. The interface does not animate every layer with equal force.

`LOCAL TRANSLATION`: Each scene has one camera verb and one content verb. Supporting notes, labels, and navigation remain still or move at reduced amplitude.

### Scroll values and animation events are different

`INFERRED FROM OBSERVATION`: Scroll controls continuous spatial values; landings, reveals, and reactions complete with authored easing.

`LOCAL TRANSLATION`: Scroll drives camera, paper edge, film travel, and the live tear. Framer/GSAP events handle photo pinning, project physics, magnetic snapping, note placement, and cover closure.

## Copyright Boundary

No Shopify assets, production bundles, illustration system, copy, shaders, or textures are included. The implementation translates interaction principles into original notebook imagery, generated archive depth layers, user project imagery, and local code.
